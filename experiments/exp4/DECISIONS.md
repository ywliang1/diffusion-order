# Exp 4 decisions and deviations

- 2026-11-17: Exp 4 calibrates its own table size (`PREREG.md`), because LLaDA did not meet the Phase 1.5b gate at any size up to 128.
- 2026-11-17: Dev calibration (1,600 CF rows per model). LLaDA: size 128 (two-hop dependent 73.0%, one-hop 96.5%; in band). Dream: no size reached 90% one-hop (81.5% at 16, 57.5% at 32, 68.0% at 64, 42.5% at 128), so the fallback branch picks 16, where two-hop dependent accuracy is 96.0%, outside the 40–80% band. H2 for Dream is therefore tested near ceiling and is expected to be weak. Main run: LLaDA 100 sources at 128, Dream 200 sources at 16 (seed 40001; task audits clean).
- 2026-11-18 (after the main run): **H1 depends on table size for LLaDA.** At 128 rows, the CF position effect is +0.290 [+0.235, +0.345] (bootstrap), so H1 is supported. At 8 rows (RQ1 study), the same contrast was +0.013 [−0.018, +0.043], so H1 was contradicted. The field-identity effect (b − a) is also large at this size: +0.240 for LLaDA and +0.253 for Dream. In the two-hop direction-b × layout-ab cell, LLaDA commits the prerequisite first in only 43% of traces and gets 42% of both fields right. That cell drives most of both effects. Read H1 as "position and field identity matter once lookup is hard", not as a clean position effect. Dream's one-hop PF − DF gap is +8.6 points [6.0, 11.2], not near 0. Its hop × order interaction, +6.2 [2.4, 10.2], still meets the H2 rule.
- 2026-11-18: The first `analyze` call wrote an empty summary. The rerun a minute later, with identical inputs, produced the report above. No input changed between the two calls, the cause is unknown, and the rerun's results are the ones reported.
- 2026-11-18: **Preregistration deviation: Exp 4's row format and table sizes were never validated by the Phase 1.5 gate.** The Mission specified that Exp 4 use the frozen Phase 1.5 format, at a table size calibrated so two-hop baseline accuracy is 40–80%, with 200 sources. Phase 1.5 and 1.5b froze no format: every variant failed the gate for both models (`experiments/phase1_5/DECISIONS.md`). What Exp 4 actually used:
  - **Row format:** V2, unfrozen. Anchor rows read `key=<q> | <p>=<prerequisite value> | h=<H> | <c>=<C>`. Mapping rows read `a=<A> | b=<B>` on two-hop items and `d=<D> | e=<E>` on one-hop items. The output is the JSON scaffold `{"a":"…","b":"…"}` or `{"b":"…","a":"…"}`, with **both** value fields masked and nothing prefilled. V2 was chosen from Phase 1.5 dev data, where it was one of two variants (with V3) that kept Direct accuracy at 90% or more for both models; the team approved V2 for Phase 1.5b. No test data informed the choice.
  - **Sizes:** chosen by Exp 4's own dev calibration (`PREREG.md`, `results/exp4/dev_calibration.json`). LLaDA used 128 rows and 100 sources; its two-hop dependent accuracy on dev was 73%, inside the band. Dream used 16 rows and 200 sources through the fallback branch; its two-hop accuracy was 96%, outside the band, because no size reached 90% one-hop accuracy. LLaDA's 100 sources (not 200) follow the PREREG compute rule for size 128.
  - **Impact:** H1 and H2 are tested on a format that passed no gate. In particular, the Phase 1.5 condition checks (Direct ≥ 90%, Shared-path at 40–80%) were not met in V2 at these sizes. Dream's H2 is tested near ceiling. Exp 4 conclusions hold for V2 at these sizes, not for a validated format. The Exp 4 PREREG recorded the calibration rule before the main run but did not log this as a departure from the Mission until now.
